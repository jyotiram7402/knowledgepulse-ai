# KnowledgePulse AI — Python Edition

Same product as the Java version, backend rewritten in **Python (FastAPI)**. Upload documents (PDF/DOCX/TXT), chat with them, get grounded answers with citations (RAG). Same database schema, same Gemini/Cloudinary, same React frontend.

## Stack

| Layer | Tech |
| ----- | ---- |
| Frontend | React 18, Vite, TypeScript, Tailwind (unchanged from Java version) |
| Backend | **Python 3.12, FastAPI, SQLAlchemy 2, Pydantic v2** |
| Auth | JWT (PyJWT) + bcrypt, role-based (USER/ADMIN) |
| DB | PostgreSQL 16 + pgvector (Neon) |
| AI | Google Gemini — `gemini-embedding-001` (768-dim) + `gemini-2.5-flash` |
| Storage | Cloudinary |
| Hosting | Vercel (frontend) + Render (backend) |

## Layout

```
backend/
  app/
    main.py            FastAPI app, CORS, health, startup seed
    config.py          env settings (pydantic-settings)
    database.py        SQLAlchemy engine/session
    models.py          ORM models (6 tables + user_roles)
    schemas.py         Pydantic request/response models (camelCase)
    security.py        bcrypt + JWT
    deps.py            auth dependencies
    routers/           auth, users, documents, chat, admin
    services/          gemini, cloudinary, extraction, chunking, rag
  requirements.txt
  Dockerfile
  .env.example
database/schema.sql    same schema (pgvector)
frontend/              same React app
render.yaml
```

## API (identical to the Java version, under `/api/v1`)

`POST /auth/register`, `POST /auth/login`, `GET/PUT /users/me`,
`POST/GET /documents`, `GET /documents/search`, `GET/DELETE /documents/{id}`,
`GET/POST /chat/sessions`, `GET/POST /chat/sessions/{id}/messages`, `DELETE /chat/sessions/{id}`,
`GET /admin/stats|users|documents`, `GET /actuator/health`.

Interactive docs: `/docs` (Swagger, auto-generated by FastAPI).

## Deploy (no local build needed)

1. **Neon** — create DB, run `database/schema.sql` (enables pgvector + tables). Copy the connection string (starts `postgresql://...` — use as-is for `DATABASE_URL`).
2. **Gemini** — get an API key at aistudio.google.com.
3. **Cloudinary** — copy cloud name, API key, API secret.
4. Push this repo to **GitHub**.
5. **Render** → New → Blueprint → pick the repo → it reads `render.yaml` (Python runtime, root `backend`). Set the `sync:false` env vars (see `backend/.env.example`).
6. **Vercel** → import repo → Root Directory = `frontend` → set `VITE_API_URL = https://<render-url>/api/v1`.
7. Set `CORS_ALLOWED_ORIGINS` on Render to your Vercel URL.
8. Verify `https://<render-url>/api/v1/actuator/health` → `{"status":"UP"}`.

## Local run (optional)

```
cd backend
python -m venv .venv && . .venv/Scripts/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # fill in values
uvicorn app.main:app --reload --port 8080
```

Frontend:

```
cd frontend
npm install
echo "VITE_API_URL=http://localhost:8080/api/v1" > .env
npm run dev
```

## Notes vs the Java version

- pgvector inserts work natively via the `pgvector` SQLAlchemy `Vector` type (no manual cast needed).
- Embeddings request `outputDimensionality=768` to match the `vector(768)` column.
- The React frontend is byte-for-byte the same — the API contract is identical.
